# Pocket Tools

A dependency-free static website for small browser utilities, served from
[`new4761.github.io`](https://new4761.github.io). The first tool is the
**Thai lottery number generator**, which builds a six-position frequency
model from historical first-prize results and (optionally) biases the
suffix positions with news from The Thaiger.

## Tools

### [Thai lottery number generator](https://new4761.github.io/tools/lottery/)

Direct endpoint: https://new4761.github.io/tools/lottery/index.html

- **Historical model.** Fetches
  [`lottery_results.csv`](https://raw.githubusercontent.com/new4761/Thai_lottery_analysis/main/lottery_results.csv)
  from [`new4761/Thai_lottery_analysis`](https://github.com/new4761/Thai_lottery_analysis),
  a monthly-updated dataset of GLO first-prize draws. It uses each digit
  position (0 = millions down to 5 = units) as a frequency model, with a
  recency decay (half-life of 24 draws by default) so recent draws influence
  generation more than older draws.
- **News-aware regeneration.** When enabled, a `news.json` file biases
  the last three positions by up to **15% of the historical weight per
  position**, with recent draw suggestions weighted more heavily than older
  ones. The historical model always supplies at least 85% of every digit's
  weight. Toggle the influence on/off from the page; expand the
  "Show the picks factored into this regen" disclosure to see the exact
  suggestions, draw dates, and weights used.
- **Multi-pick mode.** Choose 1 / 3 / 5 / 10 picks per generate. The
  first pick stays in the hero number; the rest render as a numbered
  list. A short local history is used to avoid repeating numbers
  immediately from one click to the next, and within each batch when
  possible. The generator also avoids reusing recent last-2 and last-3
  digit tails when possible.
- **Privacy.** All generation runs in the browser. No upload, no
  tracking, no accounts.

## Data source

- **Historical CSV.** Live, monthly-updated, from
  [`new4761/Thai_lottery_analysis`](https://github.com/new4761/Thai_lottery_analysis).  
  The site loads from `/lottery_results.csv` on this repo first, with fallback to the
  raw file URL when needed.  
  `lottery_results.csv` is refreshed by `.github/workflows/sync-lottery-results.yml`
  using GitHub API blob SHA checks and a persisted `lottery_results.csv.sha` file, so
  it only downloads the CSV when content actually changes. A companion
  `lottery_results.csv.meta.json` file is written at the same time with
  `sourceSha`, `sourceUpdatedAt`, and `syncedAt` for verification.
- **News JSON.** Generated by [`scripts/scrape-news.mjs`](scripts/scrape-news.mjs),
  which scrapes [The Thaiger's lottery section](https://thethaiger.com/thai-lottery/)
  and writes `news.json` with `suggestedNumbers`, `freshness`, and
  `sources`. The scraper also exports `scrapeFromHtml(html)` for
  fixture-based testing.

> **Why Thaiger-only for now?** GLO's official
> [stat-previous](https://www.glo.or.th/mission/awarding/stat-previous) and
> [orderby-time](https://www.glo.or.th/mission/awarding/orderby-time) pages
> are Nuxt SPAs that load numbers via XHR after page-load — static fetch
> (the only approach without a no-deps headless browser) cannot see them.
> The CKAN `package_show` listing at
> `https://gdcatalog.glo.or.th/api/3/action/package_show?id=dataset_c4-9_01`
> returns 9 resources that all point back to those SPA pages, plus PDF
> file-downloads at `api.glo.or.th/utility/file/download/<uuid>` that
> would require a PDF text-extraction dependency this site refuses to
> introduce. Thaiger republishes the same GLO numbers minutes after each
> official draw, so media-source signal currently dominates. Adding GLO
> cleanly would require either Playwright in the scrape-news Action or a
> pure-JS PDF parser; deferred until a dedicated backend is built.

## Workflows

- **`.github/workflows/scrape-news.yml`** — Refreshes `news.json` on the
  1st and 16th of each month. Seeds at 07:00 UTC, then polls every 30 min
  08:00–12:00 UTC (bracketing the GLO draw publish at ~08:30 UTC). A
  watchdog step fails the workflow with an `::error::` annotation if the
  scraper writes zero suggestions.
- **`.github/workflows/sync-lottery-results.yml`** — Checks the source CSV SHA on
  `new4761/Thai_lottery_analysis` and downloads/commits updated
  `lottery_results.csv` (plus `lottery_results.csv.sha`) only when the hash
  changes. It also accepts `repository_dispatch` event `lottery-results-updated`
  so source-repo data commits can trigger sync immediately.
- **`.github/workflows/test.yml`** — Runs `node --test` on every push to
  `main` and on PRs against `main`. Uses Node 22.

## Run locally

```sh
python3 -m http.server 4173
```

Open `http://localhost:4173`.

To scrape news into a local `news.json` without touching the network:

```sh
node scripts/scrape-news.mjs news.json tests/fixtures/thaiger-snapshot.html
```

## Test

```sh
node --test
```

Tests cover `buildFirstPrizeModel`, `generateModelLotteryNumber`, and
`applyNewsBias` (including the 15% cap, toggle-off purity, malformed-news
fallback, overlap on the same suffix digit, and 100-suggestion stress with
float tolerance).

## Project layout

```
lottery.mjs                  # Model builder + applyNewsBias (15% cap)
app.mjs                      # Live UI: load CSV, load news.json, render
tools/lottery/index.html     # Lottery tool page
scripts/scrape-news.mjs      # Thaiger scraper → news.json
news.json                    # Latest scraped suggestions (committed by CI)
tests/lottery.test.mjs       # Model + bias tests
tests/fixtures/              # Saved HTML for scraper regression tests
.github/workflows/           # scrape-news + test CI
```

The repository is intended for the `new4761.github.io` GitHub Pages user site.
